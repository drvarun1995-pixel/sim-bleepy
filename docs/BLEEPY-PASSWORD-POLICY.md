# Bleepy Password Policy

**Version:** 1.0  
**Effective date:** 8 August 2026  
**Applies to:** sim.bleepy.co.uk — all staff and user accounts  
**Owner:** Varun Tyagi (Bleepy)

---

## Purpose

This policy protects Bleepy accounts and organisational data. It supports our Cyber Essentials certification requirements.

---

## Scope

- All Bleepy staff accounts (Microsoft 365, GitHub, Vercel, Supabase, etc.)
- All sim.bleepy.co.uk user accounts
- Any device or cloud service that accesses Bleepy data

---

## Password requirements

1. **Minimum length:** 12 characters (no maximum length)
2. **Uniqueness:** Do not reuse passwords from other websites or services
3. **No common passwords:** Avoid predictable words (e.g. password, admin, bleepy, qwerty)
4. **No sharing:** Never share passwords with anyone, including colleagues
5. **Password manager:** Staff are encouraged to use a reputable password manager

---

## Multi-factor authentication (MFA)

MFA must be enabled on every cloud service that supports it, including:

- Microsoft 365 / Azure
- GitHub
- Vercel
- Supabase
- Google (Analytics / Maps admin)
- Hume AI and OpenAI developer accounts

---

## Account rules

- Each person must have their own username and password — **no shared accounts**
- Default passwords on routers, devices, or software must be changed before use
- Admin accounts must be separate from day-to-day accounts

---

## Brute-force protection

- Login attempts are rate-limited (maximum 10 failed attempts within 5 minutes)
- Accounts are temporarily locked after repeated failed attempts
- Cloud providers' built-in protections and MFA provide additional protection for staff accounts

---

## Compromised passwords

If you suspect a password or account has been compromised:

1. Change the password immediately
2. Notify **admin@bleepy.co.uk**
3. Review recent account activity
4. Enable or re-check MFA on affected services

---

## Staff responsibilities

- Follow this policy on all in-scope devices and services
- Use unique, strong passwords
- Report security concerns promptly

---

## Review

This policy is reviewed annually or when significant IT changes occur.
