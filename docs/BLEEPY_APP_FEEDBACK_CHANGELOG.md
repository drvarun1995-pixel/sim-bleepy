## 2026-09-02 — Advanced faculty feedback report (full spec)

Port this as one feature: generate a faculty-facing one-page PDF from a form’s responses, store every generation, let staff download or delete those PDFs (including the file in storage). **Do not copy the older teal template or the “let OpenAI invent the whole report” draft.** Those produced dull or broken PDFs and mixed pre-session “before” scores into usefulness / overall.

### What staff see

On `/feedback/forms/{formId}/responses` (admin / MedEd / CTF only):

1. **Generate advanced report** downloads a PDF immediately and also saves a copy.
2. **Saved advanced reports** lists previous PDFs for that form (newest first): filename, UK timestamp, Download, checkboxes, **Select all**, **Delete selected**, **Delete all**.
3. Delete confirms, then removes the `feedback_advanced_reports` row **and** the object in the private `feedback-reports` bucket.

Select-all padding must match the row (`px-3` + `gap-3`). Do not leave Select all at `px-1` — the checkbox will sit left of the list.

Generate is disabled when the form has zero responses. Button label must wrap (`whitespace-normal`, `h-auto`) or the default `Button` nowrap clips it.

### Why the PDF looks like this

Faculty compared our first reports with a Medtribe-style one-pager (navy header, KPI row, grouped 1–5 chart, confidence donut + key outcome, two theme columns). We match that **layout** and brand it **Bleepy**. Never print Medtribe, ChatGPT, OpenAI, or “generated by AI”.

The PDF renderer owns the layout. OpenAI only writes title, subtitle, key-outcome wording, and the two theme lists. **All numbers on the page are computed in code** from the form responses. If you let the model invent averages or invent the page structure, the report will be wrong or ugly again.

### Auth

### API

**`GET /api/feedback/forms/{formId}/advanced-report`**

Returns `{ success: true, reports: StoredFeedbackReport[] }` newest first, max 100.

Each report: `id`, `formId`, `storagePath`, `fileName`, `fileSize`, `createdAt` (camelCase from `reportStorage`).

**`POST /api/feedback/forms/{formId}/advanced-report`**

1. Load responses via `loadFeedbackFormResponses(formId)`.
2. If `totalResponses === 0` → 400 “Collect feedback before generating a report.”
3. `generateAdvancedFeedbackReport(data)` → `{ bytes, filename }`.
4. `saveFeedbackReportPdf({ formId, eventId, filename, bytes, createdBy: user.id })`.
5. Respond with the PDF (`Content-Type: application/pdf`, `Content-Disposition: attachment; filename="…"`). The browser download and the stored copy are the same bytes.

If the table insert fails after a successful upload, generation still returns the PDF. The list simply will not show that copy. Log it; do not fail the download.

**`GET /api/feedback/forms/{formId}/advanced-report/{reportId}`**

Download one saved file. 404 if the row is missing or `form_id` does not match.

**`DELETE /api/feedback/forms/{formId}/advanced-report`**

Body: `{ reportIds: string[] }` or `{ all: true }`. 400 if neither.

`deleteFeedbackReports`:

1. Select matching rows for that `form_id` (all rows if `all`, else `id IN reportIds`).
2. `storage.from('feedback-reports').remove(paths)`.
3. `DELETE` those rows. Always scope by `form_id` so one form cannot delete another form’s IDs.

Order is storage then table so a retry can clean leftover rows if the file is already gone. Return `{ success: true, deleted: number }`.

### Generation pipeline

`generateAdvancedFeedbackReport` in `lib/feedback/generateAdvancedFeedbackReport.ts`:

1. **`buildAnonymisedFeedbackPayload`**  
   Walk the form questions. Skip identity questions (name / email variants). For each remaining question attach counts only — no respondent names.  
   - `rating` → `n`, `average`, `distribution` (`1`…`scale`), `percentRatedHigh` (% scoring 4–5, or top two on a smaller scale).  
   - `yes_no` / `multiple_choice` → `optionCounts`.  
   - free text → up to 80 comments, 400 chars each, emails / known names replaced with `[redacted]`.  
   Also send `formName`, linked `event` (title, date, times, location), `coverage` (booked / attended / response rates — **do not draw these on the PDF**), `totalResponses`, and `overallAverageRating`.

2. **`overallAverageRating` is not `summary.averageRating`.**  
   The responses-page “Average rating” card still averages **every** rating answer, including “Before today’s session…”. That baseline is meant to be low. For the PDF, `headlineAverage` keeps only rating questions whose text does **not** match `/\bbefore\b/i`, then does a response-weighted mean. The payload also includes `ratingNote` telling the model not to treat before-scores as usefulness or overall.

3. **PII strip before the model sees anything.**  
   Collect emails and name tokens from signed-in respondents (skip the literal name `Anonymous`). `stripRespondentPii` redacts those and any email-shaped string in the JSON string you send to OpenAI.

4. **OpenAI call**  
   - Model: **`gpt-4o`** (do not swap without checking output).  
   - `temperature: 0.35`  
   - `response_format: { type: 'json_object' }`  
   - System prompt: you only fill **words** for a fixed faculty layout. Never invent counts. Never mention Medtribe / ChatGPT / OpenAI. Brand as Bleepy. Synthesise 3–4 short themes per column; do not dump raw comments.  
   - JSON it may return: `title`, `subtitle`, `responseCountLabel`, `sourceLabel`, `keyOutcome.heading` / `body`, `strengths[]`, `improvements[]`, `footer`.  
   - User message: the anonymised JSON payload.

5. **`parseReportJson` then `applyFacultyLayout`**  
   Layout **overwrites** KPIs, grouped chart, and highlight from measured data. OpenAI’s `strengths` / `improvements` become the two columns (`What learners valued` / `Opportunities for improvement`, max 5 bullets). `keyOutcome.heading` / `body` go into the highlight card. Quotes, recommendations, summary, extra sections, and any model-invented charts are dropped.

6. Fallbacks if the model omits them:  
   - `responseCountLabel` = `{n} RESPONSES`  
   - `sourceLabel` always forced to `Bleepy feedback summary`  
   - `footer` = `Anonymous summary of teaching feedback • Prepared from {n} submitted responses`

7. Filename: `{form-name-slug}-advanced-report-{D-Mon-YYYY}.pdf` (en-GB date from the event, else form created date). Storage path: `forms/{formId}/{iso-stamp}-{filename}`.

### Measured layout rules (`applyFacultyLayout`)

**Pre-session filter:** any rating whose question text contains `before` is excluded from KPIs, the grouped chart, and the headline average. Show those scores only if you later add an explicit before/after comparison — do not fold them into usefulness or overall.

**KPI cards (max 4):**

- One card per post-session rating: short label, `{avg}/5`, hint `{pct}% rated 4-5`, blue left bar.  
- Then **OVERALL RATING** from `headlineAverage` if that label is not already present.  
- Then a yes/no % card (green bar) if there is room.  
- Short labels: Usefulness / Interactivity / Clarity after / Confidence / Overall, else first three words.

**Grouped bar chart:** up to **three** post-session rating questions. Each cluster is scores 1–5. Title “Rating distribution”, subtitle “Number of responses by score (1-5)”. Bar colours light-blue → navy for 1→5. Count above each bar. Legend `1 2 3 4 5`.

**Highlight panel (right of the chart):**

- Prefer a yes/no question (percent Yes).  
- Else a post-session rating whose text matches `confiden`.  
- Else the first post-session rating (percent rated 4–5).  
- Donut shows that percent. Key-outcome heading comes from OpenAI if present, else a measured sentence (`27 of 29 learners answered yes` / `N learners rated confidence 4 or 5`).

**Theme columns:** omit the whole row if OpenAI returned no strengths/improvements and no `columns`. Do not invent placeholder bullets.

**Do not draw:** attendance funnel, booked/attended counts, Likert tables, quote lists, recommendation boxes, extra free-text sections. Those made the first reports look like an admin dump.

### PDF visual spec (`advancedReportPdf.ts`)

A4 (`595.28 × 841.89`), margin 28, page tint `#f1f5f9`. Helvetica / Helvetica-Bold (pdf-lib standard fonts — no custom font files).

**Header (full-bleed navy `#0b172e`):**

- Left: title (16–20pt white), subtitle 10pt `#cbd5e1` (`Topic | date | venue`).  
- Right: Bleepy logo ~28pt, then `{n} RESPONSES`, then `Bleepy feedback summary`.  
- Logo: read `public/Bleepy-Logo-128.webp`, sharp resize 256 contain on transparent, embed PNG. If missing, skip the image; still print the Bleepy text.

**KPI row:** white rounded cards, light shadow, 5px left accent (blue `#2563eb`, green `#16a34a` for %). Label muted uppercase, value ~18pt, hint 7.5pt.

**Middle row (~188pt):** two equal cards. Left = grouped chart. Right = donut + green key-outcome box (`KEY OUTCOME` in `#15803d` on `#dcfce7`). If only one of chart/highlight exists, that card goes full width.

**Bottom row:** two cards. Header bar green `#dcfce7` / amber `#ffedd5`. Title “What learners valued” / “Opportunities for improvement”. Bullets, max five, wrap so text is not clipped.

**Footer:** centred muted 8pt line, **not** a dark bar. Overflow starts a second page with an 8pt navy strip at the top. Aim for one page.

Rounded cards: svg path + 8pt radius. Do not clip titles; wrap them. The earlier bug was long question text as a chart title — that is why labels are forced short in code.

## 2026-09-02 — QR fullscreen has no close, Escape leaves a stuck overlay

**Where:** `app/qr-codes/[eventId]/page.tsx` (`QRCodeDisplayPage`)

**What broke**

Fullscreen set React `isFullscreen` (black overlay) and also called `document.documentElement.requestFullscreen()`.

1. The overlay was `fixed z-50` inside the dashboard `main.isolate`. Site nav is also `z-50` **outside** that stacking context, so it covered the top-right **Exit fullscreen** control. Scroll-to-top (`z-50`) sat on the overlay too.
2. Escape exited **native** fullscreen only. There was no `fullscreenchange` listener, so `isFullscreen` stayed true. Result: nav back, black QR overlay still covering the page, still no usable Exit.

**How**

1. Render the overlay with `createPortal(..., document.body)` and `z-[200]` so it sits above nav and dashboard isolate.
2. Always show **Exit fullscreen** top-right and again next to Test Scan Link. Hint: “Press Escape to close”.
3. Listen to `fullscreenchange` / `webkitfullscreenchange` / `MSFullscreenChange`. If there is no native fullscreen element, set `isFullscreen` false.
4. If the overlay is open and native fullscreen is **not** active, Escape closes the overlay.
5. Clicking Exit / Fullscreen again calls `exitFullscreen` and clears overlay state.

Do not leave the overlay as a `z-50` child of an `isolate` layout. Portal or a z-index above the site header.

4. Same layout on all four cards (Total responses, Average rating, Response visibility, Form template).
